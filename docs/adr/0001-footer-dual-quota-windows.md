# footer 展示 coding plan 的 5h + 7 天双配额窗口

coding plan（GLM, provider `zai-coding-cn`）的配额接口一次性返回多个窗口（`unit: 3` = 5 小时，`unit: 6` = 每周），原先 footer 只解析并展示 5h 窗口。我们决定把它们**作为两个独立仪表盘并列展示**，而不是合并成「取更耗尽的窗口」。

理由：5h 窗口是**节流阀**（随消耗滚动刷新，2 小时后就地重置），7 天窗口是**全周硬上限**（自订购起 7 天周期刷新）。二者是不同时间尺度的约束——5h 健康不代表本周还没用完，而 5h 耗尽、重置后才是 7 天窗口真正约束的时刻。独立展示让用户能同时看到两个约束，而不是被 5h 的假健康掩盖。

### 关键取舍

- **独立双窗口 vs 绑定窗口**：选独立仪表盘。代价是「谁更紧报警」的语义被放弃——7 天窗口耗尽只会让它自己那半段告警，不会把整个 plan 段标红。这是**各自报警**，不是**谁紧谁报警**。
- **展示格式**：双条全宽（各 20 格，5% 一格），不做紧凑后缀、不做窄屏降级——当前终端普遍够宽，溢出不是实际约束。
- **颜色**：健康态用基线色区分窗口（5h = `mdLink` 蓝，7 天 = `thinkingHigh` 紫灰 `178,148,187`），两种窗口共用同一套告警阈值（warning≥70 / error≥90 红黄）。选紫灰是因为它与 5h 蓝、context 绿区分度最高；复用 `thinkingMedium`/`mdLink` 已有先例，表明这套 theme token 本就允许跨语义复用。

### 影响

`parsePlanWindow()` 需改造成返回**两个窗口**的集合，而不是单个 `PlanWindow`。`planSegment()` 渲染两条 bar。`scripts/footer-preview.mjs` 保留同构镜像并同步更新。
